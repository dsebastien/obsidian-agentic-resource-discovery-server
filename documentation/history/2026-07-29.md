- New `src/app/server/registry-coordinator.ts`: **no `obsidian` import**. Owns the op mutex (`serialize`), the `disposed` guard, the restart-vs-rebuild decision (exported as the pure `requiresRestart(previous, next)`), the watcher reconcile, the embedding-retry supervision, and the scan cache.

### #3 — Sandbox `registry.search` now ranks like the real backend (option A)

- The QuickJS shim's substring scorer is gone. `src/app/mcp/registry-shim.ts` builds a **MiniSearch index with the same config and documents as `LexicalSearchBackend`** inside the isolate.
- MiniSearch's own UMD source is inlined at bundle time by a Bun macro (`src/app/mcp/minisearch-source.ts`, `with { type: 'macro' }`) and `eval`'d **lazily** in the isolate on first search — code that only filters/aggregates never pays for it. No host bridge: the isolate stays network/fs-free (BR-5 intact).
- Shared ranking config extracted: `LEXICAL_INDEX_CONFIG`, `normalizeScore`, `toIndexDoc` exported from `lexical-search-backend.ts`.
- Parity spec asserts identical **ordering and scores** vs `LexicalSearchBackend` across 7 queries. `registry.search` now returns full entries + `score` and accepts `{ limit, filter }`.
- Cost: `dist/main.js` 1.6M → 1.7M.

### #2 — Incremental rescan

- `scanSkillFolders` takes an optional `ScanCache` and returns a fresh one. Files whose `mtimeMs` is unchanged skip `readFile` + `parseSkill` + `buildSkillEntry`.
- Cache carries `publisher`/`baseUrl`; a mismatch drops it wholesale (URNs and URLs derive from them). Rebuilt each scan, so deletions fall out naturally.
- `ScanResult` gained `parsedCount` / `reusedCount` / `cache`. The coordinator threads the cache between scans.

### #1 — Persistent embedding cache

- `EmbeddingCache` seam (`get`/`set`/`save(keysInUse)`), keyed by `sha256(embedderId + dimensions + entryText)` — a model/provider switch misses by construction.
- `PersistentEmbeddingCache` over an injected `EmbeddingCacheStorage`; the plugin backs it with `embedding-cache.json` next to the plugin (vault adapter). Corrupt/unreadable payloads and failed writes degrade silently — a cache is never load-bearing.
- `SemanticSearchBackend.buildEmbeddings` only embeds misses; a full hit never even calls `embedder.load()`. `save` happens after the state flip so a write failure can't turn a good index into a failed one. `createSearchBackend(config, cache?)` → `RegistryController(cache?)` → plugin.

## Decisions

- **#3 option A via inlined MiniSearch, not a re-implemented BM25.** A hand-rolled scorer could not honestly claim "same ordering as the lexical backend" (MiniSearch's fuzzy/prefix/field-boost combination is intricate); evaluating the actual library in the isolate makes parity structural, and the parity spec catches version drift.
- **Bun macro rather than a vendored copy** of `minisearch/dist/umd/index.js`: no committed 85 KB blob, no drift from the npm dependency. Verified it survives `bun test`, `tsc`, and `Bun.build` (no `node:fs` in the bundle).
- **Embedding cache lives in a side file**, not `data.json`: settings are rewritten on every change and a megabyte of vectors has no business in there.
- **Coordinator over "make `plugin.ts` testable"**: the Obsidian import is the untestable part, so the logic moved out rather than mocking Obsidian.
