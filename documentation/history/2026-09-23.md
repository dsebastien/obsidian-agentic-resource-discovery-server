## Keep the vault's `.mcp.json` in sync (opt-in)

Why: the Obsidian Starter Kit ships this plugin preconfigured so plain `claude` in the vault discovers skills through the MCP endpoint with zero setup. The only per-install piece is the connection (port + bearer token), which users had to copy into `<vault>/.mcp.json` by hand. The kit must never ship a real token, so the plugin writes it.

- New settings `syncProjectMcpConfig` (default `false`) and `projectMcpServerName` (default `ard`). The kit ships `data.json` with `syncProjectMcpConfig: true` and no token; `ensureBearerToken` generates one on first load before the first sync.
- `src/app/settings/project-mcp-config.ts`: pure `mergeProjectMcpConfig` (unit-tested), `ProjectMcpConfigSync` (adapter I/O, empty-token skip, one notice per session on an unmergeable file), `projectMcpConfigAffected`.
- `buildMcpServerEntry` extracted from `buildMcpClientConfig`; the entry now carries `type: "http"` (required by Claude Code's `.mcp.json` for a remote server), so **Copy MCP config** gains it too.
- Triggers: after `coordinator.start()` on load; in `updateSettings` after reconcile when sync is on and it was just enabled or port/token/name changed (covers **Regenerate**).
- New rule BR-6b (opt-in, non-destructive, no churn).
- Settings: **Keep .mcp.json in sync** toggle + **Server name in .mcp.json** in the Server group. Needs a live-vault check of the pane.

Verified: `GET /health` is public (no bearer, BR-2), returns `200 {"status":"ok"}`; usable for a SessionStart health check.

Open: renaming the server leaves the old entry in `.mcp.json` (deliberate: the plugin cannot tell its old entry from a user's).

## `/search` honours `pageToken` and `federation` (Beads notesSeb-r8yz)

Why: both fields were accepted by the schema and ignored. A paging client got page one again; a federation client got local-only results with no signal. Found by the 2026-09-01 adversarial review.

- `pageToken`: offset-paged over one ranked list. Router asks the backend for `offset + pageSize + 1` hits and slices; the extra hit decides whether to emit the next `pageToken`. Relies on every backend's ranking being prefix-stable across `limit` (lexical: MiniSearch order; semantic: fixed 50-candidate pools per signal, fused then capped). Semantic depth therefore tops out around the fused pool size.
- `decodePageToken` is now strict (canonical base64 of a non-negative integer, else `null` → `400 INVALID_ARGUMENT`). Applies to `GET /agents` too, which used to restart silently at offset 0.
- `federation` per ARD §5.4 + OpenAPI `SearchResponse`: spec has no "not federated" flag and `additionalProperties: false`, and rejecting `auto` would break every client (it is the default). So: `none`/`auto` = local results; `referrals` = local results + `referrals: []` (same as the spec's reference `registry-server.py`). New rule BR-10a.
- MCP `search` tool and Code Mode `registry.search` take neither field: unchanged.
- Types: `RegistryReferral`, `ArdSearchResponse.referrals`.
