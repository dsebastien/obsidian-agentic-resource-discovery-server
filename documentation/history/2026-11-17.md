# 2026-11-17

## MCP `search` and `get_resource`: data in the text block too (#20)

Why: `search` returned only `Found N result(s).` in `content`, and `get_resource` only the display name. The data was in `structuredContent` alone, so a client that passes only `content` to the model (Msty Studio, reported in #20) got a count and no results, and could not load a resource. The MCP spec asks a tool that returns structured content to also serialize it as JSON in a text block.

- `toolSearch` and `toolGetResource` in `src/app/mcp/mcp-server.ts` now put the compact JSON of their structured content in the text block. `structuredContent` is unchanged.
- `execute` is unchanged: its text block was already the returned value as JSON.
- Specs: the text block of `search` and `get_resource` parses to the same value as `structuredContent`.

Decisions:

- The text block is JSON only, without the `Found N result(s).` summary line that #20 suggested to keep. A client can then parse it, and the count is the length of `results`.
- Compact JSON, not pretty-printed: a body can be a whole `SKILL.md`, and indentation adds size for no reader.
- The copy costs wire bytes on loopback, not model tokens, for a client that reads one field. Checked in Claude Code before the release: it gives the model `structuredContent` only, so a skill body appears once in a `get_resource` result.
